# What a machine account token can do in Secrets Manager

This table lists each Secrets Manager operation, the endpoint behind it, and the credential the Bitwarden server accepts for it. `bas-tui` builds only the rows whose credential column says "machine account". For every other row it shows the web vault page instead.

The sources are pinned to these commits.

- Server: [`bitwarden/server@a88325ae`](https://github.com/bitwarden/server/tree/a88325ae2131d59c45aa74019e05c8a7f62739bc)
- Web vault: [`bitwarden/clients@0a89c2da`](https://github.com/bitwarden/clients/tree/0a89c2daf0a3754f139b9ac0ef8f40517e636517)
- SDK: `bitwarden-sm 3.0.0`, `bitwarden-api-api 3.0.0`, and `bitwarden-core 3.0.0` from crates.io

Below, `S` is `https://github.com/bitwarden/server/blob/a88325ae2131d59c45aa74019e05c8a7f62739bc`, `SM` is `$S/src/Api/SecretsManager/Controllers`, and `BL` is `$S/bitwarden_license/src`. SDK paths are relative to the crate root in `~/.cargo/registry/src/*/`.

## How the server tells the two credentials apart

A machine account token signs in with the `client_credentials` grant and asks only for the `api.secrets` scope (`bitwarden-core-3.0.0/src/auth/api/request/access_token_request.rs:19-22`). The server issues machine account access tokens with that one scope ([`src/Api/SecretsManager/Models/Request/AccessTokenCreateRequestModel.cs:36`](https://github.com/bitwarden/server/blob/a88325ae2131d59c45aa74019e05c8a7f62739bc/src/Api/SecretsManager/Models/Request/AccessTokenCreateRequestModel.cs#L36)).

Every Secrets Manager controller has `[Authorize("secrets")]`, and that policy accepts the `api` or the `api.secrets` scope ([`src/Api/Startup.cs:150-156`](https://github.com/bitwarden/server/blob/a88325ae2131d59c45aa74019e05c8a7f62739bc/src/Api/Startup.cs#L150-L156)). The controllers then turn the caller into an `AccessClientType`: `ServiceAccount` for a machine account, `User` for a member, and `NoAccessCheck` for an organization owner or admin ([`src/Core/Enums/AccessClientType.cs:15-28`](https://github.com/bitwarden/server/blob/a88325ae2131d59c45aa74019e05c8a7f62739bc/src/Core/Enums/AccessClientType.cs#L15-L28)). The authorization handlers and repositories decide what each type may do.

The organization event log uses the `Application` policy instead. That policy requires the `api` scope and the `web` client ID ([`src/Api/Startup.cs:117-128`](https://github.com/bitwarden/server/blob/a88325ae2131d59c45aa74019e05c8a7f62739bc/src/Api/Startup.cs#L117-L128)), so a machine account token can never read it.

## Operations

"Machine account" means the server accepts a machine account token, limited to the projects and secrets the machine account has access to. "User session" means only a signed-in web vault user can do it.
